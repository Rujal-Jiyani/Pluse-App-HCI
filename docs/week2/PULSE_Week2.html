Step 1

Define goals

The five things our users (Dr. Vidhi, team leader, and Ranjan, the nurse preparing drugs) most need to do, and the features and content each one needs. Every goal traces back to an observation from Week 1.

1

Enter the child's size once, quickly, even without a scale

Needfinding: The weight is often a guess. Vidhi needs to enter weight or length with a few taps while leading the team.

Features

  • Choice of weight-based or length-based entry
  • Large, glove-friendly number keypad
  • Body-build choice (underweight / normal / overweight) for length
  • Confirm Patient Details screen with Edit

Content

  • Unit beside every number (kg, cm)
  • Accepted range: 0.5–150 kg, 30–150 cm
  • Estimated weight shown for each body build
  • "Over 50 kg: adult doses" notice
2

Get the exact volume to draw up for a crash-cart drug

Needfinding: Ranjan asks How many mL should I draw up? and worries Is this number in mg or in mL?

Features

  • Drug list grouped like the crash cart (Cardiac arrest, Arrhythmia, Seizure, Fluids)
  • Medication details before calculating
  • Result screen with the mL figure as the largest item

Content

  • Dose per kg, maximum dose, route
  • Concentration that matches the vial (e.g. 0.1 mg/mL, 1:10,000)
  • The working: 0.01 mg/kg × 15.1 kg = 0.151 mg
3

Double-check the dose with a second clinician before giving it

Needfinding: teams use closed-loop communication. Can you check that dose? Sixty and sixty, correct?

Features

  • Verify step after the result
  • Second Clinician Verification screen with one Confirm button
  • Dose Confirmed screen as the end of the task

Content

  • Read-back summary: weight, drug, dose, concentration, route, volume
  • "Verified by 2 clinicians" on the final screen
4

Catch and fix mistakes without starting over

Needfinding: One small mistake with a decimal point can seriously harm a child. Stress and noise make slips likely.

Features

  • Keypad blocks a second decimal digit and out-of-range values
  • Edit weight / Edit length on the result screen
  • Back on every screen; Home asks before clearing data
  • Automatic maximum-dose and adult-dose caps

Content

  • Plain error messages that say how to fix it
  • Badges when a rule changes the dose
5

Look up and practise rarely used drugs

Needfinding: These events are rare and stressful, so many staff have little practice with them.

Features

  • Medication Reference with search
  • Protocols & Guidelines training guide
  • Practice cases with a Reveal answer button

Content

  • Indication, concentration, child and adult dose, precautions, source
  • Step-by-step how-to and the dosing rules
Step 2

Hand-drawn paper prototype

Our original 8 frames, redrawn as paper screens, plus the error and feedback screens they were missing. Each added frame says when the "computer" (the team member swapping papers) should show it during testing.

How to make it by hand

  • One card per frame. Draw each screen on an A5 card or index card in pencil, then go over it in black pen.
  • Marker colours carry meaning. Teal for the main button and selected items, red for errors, amber for warnings, green for success. Use the same colours on every card.
  • Messages are sticky notes. Draw each error or warning strip on a small sticky note and stick it over the base screen when the tester makes that mistake, so you don't redraw the whole screen.
  • Disabled buttons are drawn in grey pencil only. Swap to the teal version once the input is valid.
  • The "Leave this calculation?" dialog is a separate small card laid on top of whatever screen is showing.

Step 3

Feedback on our initial design

We reviewed our first 8 screens (Emergency Dashboard to Verification) against the brief: what happens when the user waits, makes a mistake, or finishes a task, and whether labels and buttons stay consistent. Each issue lists the usability principle it breaks and the change we made in the prototype.

When the user waits

Initial design: no visible response to a tap; progress bar missing on screen 2; no sign that a value is being typed.

  • Every button and key changes colour and shrinks slightly the moment it is pressed, so a gloved tap is clearly registered.
  • Blinking cursor in the number field; the value appears as it is typed.
  • Progress bar (Patient Size → Medication → Calculation → Verify) on every step of the task.
  • Confirm stays greyed out until the value is valid, showing what the app is waiting for.
  • Doses are calculated on the tablet, so results appear instantly with no loading screen.

When the user makes a mistake

Initial design: any number accepted (0 kg, 1500 kg); Next always active; no way back except the back arrow.

  • Accepted range always shown under the field.
  • Out-of-range value: red border, warning icon and message, e.g. "Maximum length is 150 cm. Allowed range: 30–150 cm."
  • The message waits 0.6 s after typing stops, so it doesn't flash while typing "0." on the way to "0.8".
  • Edit Measurement / Edit weight return to the keypad with the old value filled in.
  • Home asks "Leave this calculation?" before clearing data.

When the user finishes

Initial design: tapping Confirm on screen 8 led nowhere; no proof the check happened.

  • Dose Confirmed screen with a large animated green tick.
  • Final summary: weight, drug, dose, concentration, route, "Verified by 2 clinicians", and the volume to draw highlighted in bold.
  • All four progress steps show a tick.
  • Home button (top right) starts the next drug or patient.
